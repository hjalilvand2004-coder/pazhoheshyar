# راهنمای استقرار پژوهشیار۳۶۰ روی سرور ویندوز — پورت 8088

سرور تولیدی اکوسیستم دانشجویار۳۶۰ (188.212.96.235) **ویندوزی** است؛ این راهنما برای همان سرور نوشته شده است (راهنمای لینوکس/systemd در `README-FA.md`). بستهٔ پرتیبل ویندوز به نصب پایتون یا Node نیاز ندارد.

---

## ۱) اجرای سریع (بستهٔ پرتیبل)

1. از بخش **Releases** گیت‌هاب، `Pazhoheshyar360-Windows-v1.0.4.zip` (یا جدیدتر) را دانلود و در مسیری مثل `C:\pazhoheshyar360` استخراج کنید.
2. روی `START-WINDOWS.bat` دابل‌کلیک کنید — از نسخهٔ 1.0.4 پورت پیش‌فرض **8088** است و اگر پورت اشغال باشد از قبل هشدار فارسی می‌دهد (خطای 10048 نمی‌گیرید).
3. صحت‌سنجی:

| نشانی | انتظار |
|---|---|
| `http://localhost:8088` (روی خود سرور) | صفحهٔ اصلی |
| `http://188.212.96.235:8088` (از بیرون) | همان صفحه — نیازمند گام ۲ |
| `http://188.212.96.235:8088/api/v1/services` | پاسخ JSON با وضعیت ok |

> **بسته‌های قدیمی (تا v1.0.3):** اسکریپت استارت پورت را اجباراً روی 8000 می‌گذاشت؛ اگر 8000 اشغال باشد با خطای `10048` بسته می‌شود. با همان بستهٔ قدیمی هم می‌توانید مستقیم فایل اجرایی را با پورت 8088 بالا بیورید:
>
> ```powershell
> cd C:\pazhoheshyar360
> $env:PORT = "8088"
> .\pazhoheshyar360-server.exe
> ```

## ۲) فایروال ویندوز + گروه امنیتی ابر

قانون فایروال ویندوز (که در سرور اجرا شده است):

```powershell
New-NetFirewallRule -DisplayName "Allow TCP 8088" -Direction Inbound -Protocol TCP -LocalPort 8088 -Action Allow -Profile Any
```

اگر با این قانون هم از بیرون باز نشد، تقریباً همیشه علت **گروه امنیتی/فایروال لایهٔ ابر** (Security Group / NSG پنل ارائه‌دهندهٔ سرور) است — قانون ورودی TCP 8088 را آنجا هم اضافه کنید. تست بیرونی:

```powershell
Test-NetConnection 188.212.96.235 -Port 8088     # روی سرور
curl -v http://188.212.96.235:8088/api/v1/services   # از هر ماشین بیرونی
```

نکته: پورت 8000 روی سرور اشغال است (علت خطای 10048 قبلی)؛ سامانه‌های دیگر اکوسیستم روی پورت‌های خودشان هستند — پژوهشیار باید فقط 8088 را بگیرد.

## ۳) شروع خودکار پس از ری‌استارت سرور

بستهٔ 1.0.4 فایل `SERVICE-WINDOWS.bat` دارد: سرور را بدون مرورگر و بدون `pause` اجرا می‌کند و لاگ را در `server-log.txt` می‌نویسد. برای شروع خودکار با Task Scheduler (در PowerShell با دسترسی Administrator):

```powershell
schtasks /Create /TN "Pazhoheshyar360" /SC ONSTART /RU SYSTEM /RL HIGHEST /TR "C:\pazhoheshyar360\SERVICE-WINDOWS.bat"
```

(مسیر `C:\pazhoheshyar360` را با مسیر واقعی استخراج بسته عوض کنید.) تست دستی: `schtasks /Run /TN "Pazhoheshyar360"` و مشاهدهٔ لاگ: `Get-Content C:\pazhoheshyar360\server-log.txt -Tail 20`. حذف وظیفه: `schtasks /Delete /TN "Pazhoheshyar360" /F`.

## ۴) ورود یکپارچه (SSO) — بدون تنظیم اضافه در این سامانه

پیش‌فرض‌های بسته از ابتدا روی استقرار تولیدی قفل است:

| فیلد | مقدار |
|---|---|
| Issuer | `http://188.212.96.235:8086` |
| Client ID | `pajouhyar360` (همان ثبت پنل پرتال) |
| Redirect URI | `http://188.212.96.235:8088/api/v1/auth/sso/callback` |
| URI پس از خروج | `http://188.212.96.235:8088/?loggedOut=1` |

تنها پیش‌نیاز باقی‌مانده **سمت پرتال** است: ردیف سامانه در پنل «مدیریت سامانه‌ها» پرتال باید تیک **فعال** بخورد و **ذخیره** شود (در صورت لزوم بلوک `pajouhyar360` را مطابق `deploy/portal-clients.json.snippet.json` به `data/clients.json` پرتال اضافه و سرویس پرتال را ری‌استارت کنید). تست ثبت از هر جایی:

```
http://188.212.96.235:8086/protocol/openid-connect/auth?response_type=code&client_id=pajouhyar360&redirect_uri=http%3A%2F%2F188.212.96.235%3A8088%2Fapi%2Fv1%2Fauth%2Fsso%2Fcallback&scope=openid&state=t&nonce=t&code_challenge=aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa&code_challenge_method=S256
```

پاسخ «کلاینت ناشناس» یعنی ثبت پرتال هنوز فعال نشده؛ صفحهٔ ورود پرتال یعنی ثبت سالم است.

## ۵) عیب‌یابی سریع

| نشانه | علت | اقدام |
|---|---|---|
| خطای `10048` هنگام استارت | پورت اشغال (قبلاً 8000) | نسخهٔ 1.0.4 خودش هشدار می‌دهد؛ پردازش اشغال‌کننده: `netstat -ano \| findstr :8088` |
| محلی بالا می‌آید، از بیرون نیست | فایروال/گروه امنیتی ابر | گام ۲ |
| «کلاینت ناشناس» هنگام ورود SSO | ثبت پرتال فعال نشده | گام ۴ |
| «ردِ redirect_uri» | ناسازگاری نشانی callback | باید دقیقاً `http://188.212.96.235:8088/api/v1/auth/sso/callback` باشد |
| سرور با بستن پنجره قطع می‌شود | اجرای foreground است | گام ۳ (Task Scheduler) |
| داده‌های قبلی گم شد | اجرای exe از مسیر دیگر | همیشه از همان پوشه اجرا کنید؛ داده‌ها در `data\` کنار `exe` هستند |

## ۶) به‌روزرسانی

۱) دانلود zip نسخهٔ جدید و استخراج در پوشهٔ جدید؛ ۲) کپی پوشه‌های `data\` و `uploads\` از پوشهٔ قبلی به جدید؛ ۳) اجرای `START-WINDOWS.bat` (یا ری‌استارت وظیفهٔ Task Scheduler). پایگاه‌داده SQLite است و با کپی همین دو پوشه منتقل می‌شود.
